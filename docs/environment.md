# Environment contract

Schemas live in [`packages/contracts/src/env.ts`](../packages/contracts/src/env.ts). `.env.example` is a copy-ready **local-only** configuration with fixed, loudly non-production secrets; deployment injects distinct secrets through the platform secret store or `/run/secrets` files. Environment validation reports variable names, never values.

- Local development uses `MODEL_PROVIDER=codex-cli` and `MODEL_NAME=default`, with no `MODEL_API_KEY`. Run `codex login` on the host first when needed. Local Compose bind-mounts that host auth file read-only only to seed its isolated `codex-home` volume; the worker uses the isolated volume afterward. Do not place host Codex credentials in `.env` or deployment secrets.
- A hosted model provider instead needs its provider-specific API key in deployment secret storage. It must not reuse Codex host-login credentials. For an OpenAI-compatible gateway such as OpenRouter, set `MODEL_PROVIDER=openai`, put the gateway model id (for example a vendor-prefixed slug) in `MODEL_NAME`, the API key in `MODEL_API_KEY` (secret storage only), and the gateway chat-completions origin in the optional worker variable `MODEL_BASE_URL`. Leave `MODEL_BASE_URL` unset for first-party providers; it is rejected for `codex-cli`.
- Local Compose runs its migration service automatically before web and worker start. Production migrations remain a reviewed, manual, one-at-a-time operation; see [`docs/runbooks/migration-rollback.md`](runbooks/migration-rollback.md).
- `HYPERMAIL_TENANT_ROUTES` is the production routing contract. It is a JSON object keyed by User UUID, with a distinct private Hypermail endpoint/key per User. Worker readiness initializes and verifies every configured route. When this variable is absent, only `NODE_ENV=development` may use the legacy single-owner `HYPERMAIL_URL`/`HYPERMAIL_KEY` route; production fails closed and public external-agent execution remains unavailable.

- Web receives auth, recovery recipient, Hypermail server credentials, VAPID keys, application origin, DB URL, a dedicated private attachment directory, attachment byte/age limits, and the private approved-send endpoint/token.
- Worker receives DB/Hypermail/model credentials, `ATTACHMENT_TEMP_DIRECTORY`, and bounded polling, retention, and safety settings. Its Hindsight client contract is `HINDSIGHT_URL`, optional `HINDSIGHT_API_KEY`, exact `HINDSIGHT_EXPECTED_VERSION=0.9.1`, request timeout and single-file byte limits. Files are uploaded one at a time. Durable mailbox-memory events retry indefinitely. Their base delay, maximum delay, fenced claim lease, and scheduler interval are configured by the strict fields below. The URL must be an exact private HTTP(S) origin with no credentials or path. The optional key belongs only in `WORKER_ENV_FILE` and is used only when an auth-enabled private endpoint is deployed. The attachment directory is the deployment-fixed private volume shared only with web and Hypermail; supported files are read one at a time and cleaned after Hindsight ingestion.
- The Hindsight service receives a separate `HINDSIGHT_ENV_FILE`. It must contain `HINDSIGHT_API_LLM_PROVIDER`, `HINDSIGHT_API_LLM_MODEL`, and the provider's `HINDSIGHT_API_LLM_API_KEY` when that provider requires one; an OpenAI-compatible gateway also sets `HINDSIGHT_API_LLM_BASE_URL` to its chat-completions origin. The pinned full image uses local embeddings and local reranking, so do not send extra embedding/reranker credentials by default. `.env.hindsight.example` is the local template. Never merge it into `.env`, `WEB_ENV_FILE`, browser configuration, or logs.
- Backup jobs receive only DB URL, target, retention, and two separate `/run/secrets` age identity paths (one database domain and one private-state domain), plus backup-only object-store and failure-alert secret files.
- Provider access/refresh tokens and IMAP passwords are entered during Hypermail account onboarding and remain only in its encrypted persistent state. Gmail OAuth bootstrap configuration is optional and belongs only to the private Hypermail service: `HYPERMAIL_GMAIL_CLIENT_ID`, the issued optional `HYPERMAIL_GMAIL_CLIENT_SECRET`, and `HYPERMAIL_GMAIL_REDIRECT_URI`. Do not inject these values into web, worker, or browser/public configuration. If the client fields are absent, Gmail onboarding is honestly unavailable; Outlook and IMAP do not use these variables. See the [Google OAuth runbook](runbooks/google-oauth.md) for Console setup, credential handling, test acceptance, and production requirements.
- Register the redirect URI with Google **exactly** as the Hypermail value. The local default is `http://localhost:8080/oauth/gmail/callback` (same-origin, no trailing slash); each deployed origin must use its own exact `https://…/oauth/gmail/callback` value. The web callback is public as part of the web origin, but Hypermail itself remains private.
- Store production Gmail configuration in the Hypermail-only secret/env file (`HYPERMAIL_ENV_FILE`), not a shared application env file. Treat the client secret as a secret; keep the client ID and redirect URI with that service configuration to prevent accidental delivery to other containers. To rotate or change it, update the Google registration and the Hypermail-only secret file, redeploy/restart Hypermail, validate its readiness, then revoke the prior secret. Do not log values or paste rendered env output into tickets.
- Compose rendering proves only interpolation and private-service delivery; it is not live Gmail-provider validation. Validate an authorized onboarding/callback flow separately with the registered provider before treating Gmail as available.
- Local Compose builds Hypermail from the exact `hypermail-mcp` version in `apps/hypermail/package.json`; no local `HYPERMAIL_IMAGE` value is required. Production publishes and pins the image built from that same package version by digest.
- Production exposes only the proxy/web route. Database, worker, Hypermail, and the approved-send endpoint resolve only on the private network. The approved-send endpoint must durably deduplicate `Idempotency-Key`; direct Hypermail v0.7 MCP send is not an exactly-once substitute.
- `HYPERMAIL_PROTOCOL_VERSION=2025-11-25` is verified for local initialization against the pinned v0.7.26 image. This does not prove provider tools or the production contract; keep those release blockers until the full live matrix passes. See [`docs/contracts/hypermail.md`](contracts/hypermail.md).
- The attachment directory must be a dedicated non-symlink directory inaccessible to other workloads (not `/tmp`) and shared only by web, worker, and the Hypermail component that materializes attachment files. Startup must run owned-orphan cleanup before accepting downloads.

## Hindsight worker settings

| Variable | Default/bound | Purpose |
|---|---:|---|
| `HINDSIGHT_URL` | required | Exact private API origin, normally `http://hindsight:8888` |
| `HINDSIGHT_API_KEY` | optional, 16+ characters | Worker-only bearer credential for an auth-enabled endpoint |
| `HINDSIGHT_EXPECTED_VERSION` | required literal `0.9.1` | Fail-closed compatibility pin; readiness checks `/health/ready`, `/version`, then bounded `/openapi.json` |
| `HINDSIGHT_REQUEST_TIMEOUT_MS` | 30,000; 1,000–120,000 | One API request ceiling |
| `HINDSIGHT_MAX_FILE_BYTES` | 10 MiB; max 25 MiB | Worker-side single-file ceiling |
| `MAILBOX_MEMORY_RETRY_BASE_DELAY_SECONDS` | 5; 1–3,600 | Initial durable event and agent-memory deferral delay |
| `MAILBOX_MEMORY_RETRY_MAXIMUM_DELAY_SECONDS` | 900; 1–86,400 and not below base | Exponential retry delay cap; retries remain indefinite |
| `MAILBOX_MEMORY_CLAIM_LEASE_SECONDS` | 3,600; 2–3,600 and longer than request timeout | Fenced event claim lease, renewed around provider and Hindsight operations |
| `MAILBOX_MEMORY_SCHEDULER_INTERVAL_SECONDS` | 5; 1–60 and shorter than lease | Durable event recovery/delivery loop interval |

Compose also caps Hindsight conversion batches at 50 MiB/five files and supplies configurable CPU/memory limits. These server limits do not replace the stricter worker checks. Production readiness must fail closed if `/health/ready` is unavailable, `/version` reports an API version other than `0.9.1`, required feature flags are absent, or the bounded OpenAPI document omits any bank configure/create, retain, recall, file-upload, operation-status, or bank-delete method.
